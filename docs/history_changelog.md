# Posta 開發歷史與變更日誌

本文件完整記錄了 Posta 專案從最初的開發規畫，到後續進行的大規模架構重構與大檢修實作歷史。

---

## 1. 歷史開發計畫 (原 00_plan.md 存檔)

### 1.1 系統架構概念 (起點)
為了將舊有的「線性處理管線 (Linear Pipeline)」升級為「有向無環圖 (DAG)」架構，最初規劃了以下核心元件：
* **Node (節點)**：獨立圖像操作單元。
* **Connection (連線)**：定義資料流向，支援一對多與多對一。
* **Graph Engine (執行引擎)**：透過拓撲排序計算執行順序，調度記憶體。

### 1.2 四大開發階段
* **Phase 1: 核心資料結構與引擎** (已完成) - 建立 `Node`, `Pin`, `Connection` 與 `Graph` 拓撲運算。
* **Phase 2: 演算法模組化** (已完成) - 剝離舊演算法，包裝為獨立節點。
* **Phase 3: 視覺化節點編輯器** (已完成) - 使用 `QGraphicsScene` 實作拖曳、連線等 UI 元件。
* **Phase 4: 系統整合與非同步計算** (已完成同步整合；非同步排入後續優化計畫)。

## 2. 大檢修修改紀錄 (2026-05-28)

在此次大檢修中，將原有集中在 `main.py` 的業務邏輯進行了深度重構與模組解耦，以解決雙向耦合、冗餘運算與潛在崩潰問題。

### 2.1 模組化解耦改動
* **UI 圖元與 MainWindow 解耦**：新增 `GraphSceneController`，由場景顯式持有，移除圖元透過 `scene.views()[0].main_window` 反查主視窗的隱式依賴。
* **節點工廠抽離**：新增 `node_factory.py`，統一節點建立與事件綁定路徑，避免事件監聽器漂移。
* **輸入圖片狀態抽離**：新增 `input_session.py` 與 `image_importer.py`，將剪貼簿、拖曳與檔案匯入邏輯統一由 `ImageImportManager` 與 `InputSession` 管理。
* **序列化路徑純化**：重構 `graph_state.py`，匯出狀態時改接收位置字典，不再依賴並匯入 `NodeItem` 視覺類別。
* **變更通知解耦**：場景的操作改為發送訊號 (`graph_structure_changed`)，主視窗再行評估或存檔，解除了強耦合。

### 2.2 效能與穩定性修復 (Bug Fixes)
* **剪貼簿圖片貼上防呆**：修復了當剪貼簿為空或無效格式時，`np.frombuffer` 解析導致崩潰的問題。
* **Dirty 標記下游傳遞修復**：修正了 `InputPin.connect` 未將連線寫入 `_downstream_edges` 的 Bug，確保參數變動能正確沿下游傳播。
* **Switcher 節點過度評估優化**：調整定時重算邏輯，僅在 Switcher 真正切換索引時才標記為 Dirty 並觸發 `evaluate_graph`。
* **Halftone 節點向量化**：將原本以雙迴圈處理的半調子網點演進改為 NumPy 網格矩陣運算，大幅加速大圖處理速度。
* **Grain 節點快取**：為雜訊加入 `seed` 參數並進行快取，避免每次評估都重新生成亂數且畫面持續跳動。
* **Pin 類型連線防呆**：將 UI 連線規則與引擎 `can_connect_pins()` 對齊，拖線時動態降低不相容 Pin 的透明度，並加入磁吸效果。
* **單節點例外處理**：為 `Graph.evaluate` 的各個節點加上 `try-except` 保護，運算失敗時改以紅框顯示並將錯誤寫入 ToolTip，不再使整支程式崩潰。
* **Redo 支援**：補齊完整的 `redo_stack`，與既有的 Undo 歷史堆疊搭配，並綁定快捷鍵。

## 3. 檢修前/後架構對比

| 功能模組 | 重構前狀態 | 重構後狀態 (現狀) |
|---|---|---|
| **節點建立** | 散落在 `main.py` 內部，新建與還原邏輯不一致 | 由 `node_factory.py` 統一管理，共用事件綁定 |
| **圖片匯入** | 剪貼簿、拖曳、對話框各自實作狀態寫入 | 集中至 `InputSession`，匯入走統一的 `ImageImportManager` |
| **歷史紀錄** | 僅支援 Undo，無 Redo 且容易遺漏清空 | 支援完整的雙向 Undo/Redo 堆疊 |
| **連線安全性** | 僅靠 UI 限制，引擎層可被繞過 | UI 與引擎層共用 `can_connect_pins()` 雙重驗證 |
| **例外容錯** | 節點發生 OpenCV 錯誤時整支程式崩潰 | 捕獲例外，標記單一節點為 Error 狀態並顯示紅框 |
